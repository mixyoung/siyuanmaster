## 6. 2026-10-06 回读兼容后续修复

### 官方行为与实现边界

- 思源 `v3.8.6/kernel/model/export.go` 的 `exportMarkdownContent0` 使用 `NewProtyleExportMdRenderer`；`kernel/go.mod` 固定 Lute commit `c8cee1b0c658`。该渲染器的 `renderDocument` 最后写一个 LF。虽其内部也会修剪部分外层空白，插件**不复制通用 trim 行为**，只兼容已证实的窄 EOF LF 差异。
- 官方 `MoveDocs → moveDoc → moveTree` 在更新块树路径后调用 `sql.MoveTreeQueue`；API 成功不等于插件 SQL 查询已经观察到新路径。原有短窗口存在过早判定失败的风险，不以此放松结构谓词。
- `src/document-readback.ts`：先接受逐字节相等，或输入没有末尾 LF/CR、导出恰好多一个 LF；**只有空输入**额外接受精确的默认空段落 U+200D + LF。官方 `exportTree` 在空段落 `FirstChild == nil` 时补 `editor.Zwj`（`export.go:3525–3528、3577–3578`），本轮实机导出为两个码点 `8205, 10`。不删除正文中的零宽字符；重复占位、额外空格/LF、正文、内部换行、CRLF、双空格、IAL、截断及多余/删除 LF 仍严格。
- `update_note` 复用现有 `verifyReadback`，回读返回导出原文；写前 snapshot/verifyCurrent 仍用原始 UTF-8 SHA-256。`computeContentHash`、`edit_block`、确认门禁和标签部分成功未修改。
- `waitForStructureState`：立即读取，总预算 5s（读取耗时也计入），轮询间隔最多 250ms，最多 21 次。单次读等待受剩余预算约束；超时/读异常返回 `outcome_unknown`，可信但持续不匹配返回 `verification_failed`；停止后不继续读取，不重发写 API，迟到结果不能变更已返回响应。
